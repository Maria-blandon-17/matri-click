Cómo se relacionan las tablas del sistema

Este proyecto está escrito en TypeScript, no en un lenguaje orientado a objetos clásico — así que no tiene "clases" con herencia ni métodos propios. Lo que sí tiene, y cumple el mismo papel para leer el proyecto, son 9 entidades (tablas de la base de datos, definidas en lib/types/database.types.ts) con relaciones fijas entre ellas. El diagrama de abajo muestra esas entidades como si fueran clases: cada caja es una tabla, cada línea es una llave foránea que conecta dos registros.

PK llave primaria (id único de cada fila) FK llave foránea obligatoria (siempre apunta a otra fila) FK? llave foránea opcional (puede quedar sin asignar) enum solo acepta un valor de una lista fija

Cómo leer las flechas

Una flecha A "1" → "0..*" B se lee "un A puede tener muchos B, pero cada B pertenece exactamente a un A". Por ejemplo: grados → grupos significa que un grado (ej. "Quinto") puede tener varios grupos (5A, 5B), pero cada grupo pertenece a un solo grado. Las relaciones marcadas FK? en el diagrama (director de grupo, acudiente de un estudiante, vínculo de un perfil) pueden quedar vacías — por eso en el código esos campos son string | null.

Actualización: nuevo estado en matriculas

Desde supabase/migrations/0007_solicitudes_matricula.sql, estado_matricula tiene un cuarto valor: Pendiente (antes solo Activa / Cancelada / Finalizada). Se usa cuando un acudiente solicita la matrícula desde su cuenta en vez de crearla un admin — queda en espera hasta que un admin la apruebe (pasa a Activa) o la rechace (pasa a Cancelada). El resto de la tabla no cambió: sigue siendo la misma fila apuntando a un estudiante, un periodo y un grupo.

El archivo de tipos está escrito a mano (no generado con supabase gen types), así que si el esquema real cambia en Supabase, este diagrama y lib/types/database.types.ts hay que actualizarlos juntos.
